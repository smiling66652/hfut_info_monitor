## 二、四个根因

### 1. 解析器只认一套 CMS（主因）

`extract_items_standard()` 的正则只匹配 `info/{栏}/{id}.htm` 这一种详情页形态。
但合工大各子站并存多套 CMS，大量站点用的是
`/YYYY/MMDD/c{栏}a{id}/page.htm`（研招、团委、科研院、社科处、电气、机械等）。

结果：**URL 明明 200 可达，解析器却返回 0 条**，然后被误判为"站点失败"。

### 2. 浏览器兜底自锁死循环

`main()` 里"上次失败就启用浏览器兜底"，但 **Playwright 根本没装**：

```
失败 → 标为失败 → 下次强制走浏览器 → Playwright 不可用 → 又失败 → 再标记
```

一次失败导致该栏目永久锁死在浏览器模式，`fail_count` 就是这么涨到 16 的。

### 3. 栏目 URL 大面积失效

| 栏目 | 原 URL | 实况 |
|---|---|---|
| 电气学院 | `dqxy.hfut.edu.cn` | **域名已废弃**（DNS 解析为 IPv6 link-local），现为 `ea.hfut.edu.cn` |

### 4. `list_url` 循环变量泄漏

`as_completed` 回调里写 `failed_sites[channel_name] = {"url": list_url, ...}`，
`list_url` 是外层 `for channel in CHANNELS` 的残留值，
导致**所有失败栏目都被记成同一个（最后一个）URL** ——
这就是 `failed_sites.json` 里研招/团委的 URL 都显示成 `cxcy.hfut.edu.cn` 的原因。

## 三、修复内容

| # | 改动 | 位置 |
|---|---|---|
| 1 | 新增 **通用解析器** `extract_items_generic()`：只按详情页 URL 形态提取，兼容网站群 `/YYYY/MMDD/c…/page.htm` 与老 CMS `info/…htm`；**日期优先从 URL 还原**（比解析页面文本更稳） | `hfut_scanner.py` 顶部 |
| 2 | 站点专属解析器失配时自动回退通用解析器 | `extract_items_from_list_html()` |
| 3 | 浏览器兜底加**可用性闸门**：Playwright 不可用则不切浏览器；单栏目累计失败 ≥2 次直接跳过 | `main()` |
| 4 | 修复 `list_url` 泄漏，改用 future 返回的 `channel_url` | `main()` |
| 5 | **全部请求绕过本机代理**（本机 `http_proxy` 对 `hfut.edu.cn` 返回 502，直连仅 0.1s）：urllib 走无代理 opener、requests 设 `trust_env=False` | `fetch()` / `fetch_requests_bs4()` / `sentinel_check()` |
| 6 | 重写 18 个栏目 URL；移除 3 个已废弃域名 | `CHANNELS` |
| 7 | 哨兵检查 HEAD 失败时退化 GET；统一忽略证书校验并屏蔽告警噪音 | `sentinel_check()` / 导入区 |
